# SpreadSheetAi POC — Backend Implementation Plan

Status: draft for review · Date: 2026-09-19
Implements: [requirements.md](requirements.md) · Interface: [contract.md](contract.md)

The frontend is built in parallel against `contract.md`. The backend owns
that contract. Any change to it is agreed first and made in `contract.md`
before code.

Versions this plan was checked against: Phoenix 1.8.14, `sagents` 0.15.1,
`langchain` 0.14.1, `req_llm` 1.24.0. Sagents is at 0.x and changes quickly.
Pin it at `~> 0.15.1`, and re-check this plan against its CHANGELOG before
upgrading.

## 1. Architecture

```
            Vue SPA
   REST /api/*   │   WebSocket /socket (token auth)
                 ▼
 ┌───────────────────────────── SpreadSheetAiWeb ─────────────────────────────┐
 │ SheetController  ConversationController  SocketTokenController             │
 │ UserSocket ── SheetChannel "sheet:<id>"                                    │
 │            └─ ConversationChannel "conversation:<id>"                      │
 │ Presence (Phoenix.Presence)                                                │
 └──────┬──────────────────────────────────────────────┬─────────────────────┘
        │ Sheets API                                     │ Coordinator / AgentServer
 ┌──────▼──────────── SpreadSheetAi.Sheets ─────┐  ┌─────▼──── Sagents ──────────────┐
 │ Registry + DynamicSupervisor                  │  │ AgentServer per conversation    │
 │ Sheets.Server (GenServer, one per open sheet) │◄─┤ Factory: ChatReqLLM (OpenRouter)│
 │   Engine (pure) → Persister (Repo txn)        │  │ Middleware.SheetTools (tools +  │
 │   → PubSub "sheet_events:<id>"                │  │   linked-sheet context)         │
 └──────┬────────────────────────────────────────┘  └─────┬───────────────────────────┘
        ▼                                                  ▼
     Postgres: sheets, sheet_columns, sheet_rows, sheet_changes,
               conversation_sheets, sagents_conversations / agent_states / display_messages
```

Key properties:

- **One process per sheet.** Every change to a sheet, from a user's channel
  or an AI tool, goes through `Sheets.Server`. The server applies changes
  one at a time.
- **Write-through.** The server validates and applies an op in memory,
  writes it to Postgres in one transaction, and only then updates its state
  and broadcasts.
- **Postgres is the source of truth.** A sheet process can be killed at any
  time, and it reloads from Postgres on the next use.
- **Clean layering.** The core layer (`SpreadSheetAi.*`) never calls
  `Endpoint`. It broadcasts plain Elixir terms on internal PubSub topics,
  and the channels translate them into contract JSON.

The existing conventions apply throughout:
- Schemas never call `Repo`. Each has a `*_queries.ex` sibling that returns
  an `Ecto.Query`.

- Registry and DynamicSupervisor children are named.

## 3. Data model

One migration per table, generated with `mix ecto.gen.migration`.

**`sheets`**
| column | type | notes |
|---|---|---|
| id | binary_id PK | |
| name | string, not null | not unique |
| owner_id | binary_id → users, not null | `on_delete: :restrict` |
| version | integer, not null, default 0 | goes up by one for every applied op |
| timestamps | utc_datetime | `updated_at` is touched on every op |

**`sheet_columns`**
| column | type | notes |
|---|---|---|
| id | binary_id PK | may be supplied by the client (contract §6) |
| sheet_id | → sheets, not null, `on_delete: :delete_all` | |
| name | string, not null | |
| name_key | string, not null | `lower(trim(name))`. Unique index `(sheet_id, name_key)` |
| column_type | string, not null | text / number / boolean / date |
| is_label | boolean, not null, default false | partial unique index `(sheet_id) WHERE is_label` |
| position | integer, not null | 0-based. Renumbered on insert, move or delete |

**`sheet_rows`**
| column | type | notes |
|---|---|---|
| id | binary_id PK | may be supplied by the client |
| sheet_id | → sheets, not null, `on_delete: :delete_all` | |
| label | string, not null | the label column's value |
| label_key | string, not null | `lower(trim(label))`. Unique index `(sheet_id, label_key)` |
| position | integer, not null | 0-based |
| values | jsonb map, not null, default `{}` | `%{column_id => value}` for non-label columns. Nulls are left out |

**`sheet_changes`** (change log, P-3)
| column | type | notes |
|---|---|---|
| id | binary_id PK | |
| sheet_id | → sheets, `on_delete: :delete_all` | unique index `(sheet_id, version)` |
| version | integer, not null | the version this op produced |
| op | jsonb, not null | the `AppliedOp` |
| actor_type | string, not null | `user` / `agent` |
| actor_user_id | → users, nullable | set when `actor_type = user` |
| conversation_id | binary_id, nullable | set for agent changes. Also set for user changes made while in a conversation |
| client_op_id | binary_id, nullable | |
| inserted_at | utc_datetime | |

**`conversation_sheets`** (session–sheet links, ST-1). Created in Phase 6,
because it references `sagents_conversations`, which `mix sagents.setup`
creates.
| column | type | notes |
|---|---|---|
| id | binary_id PK | |
| conversation_id | → sagents_conversations, `on_delete: :delete_all` | unique `(conversation_id, sheet_id)` |
| sheet_id | → sheets, `on_delete: :delete_all` | |
| created_here | boolean, not null, default false | |
| last_access | string, not null | created / opened / read / written |
| first_accessed_at, last_accessed_at | utc_datetime | |

Links are upserted with `on_conflict`: `last_access` and
`last_accessed_at` are updated, and `created_here` is OR-ed.

**Why this layout.** Rows keep their values as a JSON map keyed by column
id. So:
- `set_cells` is one `UPDATE` per touched row;
- renaming a column never touches rows;
- deleting a column is one `UPDATE … SET values = values - column_id`;
- positions are plain integers, renumbered with one `update_all`, which is
  fine at POC sizes.

**Future: formulas.** Formulas are out of scope, and this layout doesn't
block them:
- Formula text goes in a new `formulas jsonb` column on `sheet_rows`, keyed
  by column id like `values`.
- Computed results are **not stored**. `values` holds only literal inputs,
  and a formula cell has an entry in `formulas` and none in `values`.
- The sheet process computes every formula when it loads, and recalculates
  in memory after each edit. An edit writes only the cells that changed,
  however many cells depend on them.
- Reads, tools and the UI get computed values from the process.
  `op_applied` carries the recalculated cells alongside the op, even
  though they're never written to Postgres.
- Formulas reference stable row and column ids internally, and are shown
  to users by name. Inserting, moving or renaming rows and columns
  therefore never rewrites formulas.
- The real work is in the engine: parsing, an in-memory dependency graph
  rebuilt on load, cycle detection, recalculation, and coordinating
  processes for references between sheets.
- Costs of not storing results:
  - loading a big sheet means evaluating all of its formulas;
  - anything reading Postgres directly doesn't see computed values;
  - a formula that reads another sheet makes loading one sheet start the
    other.
- Functions that are expensive or change on each run (external calls, AI,
  `NOW()`) may need their results cached as an exception.

## 4. Sheet engine (pure)

**`Sheets.State`** holds `id, name, owner, version, columns (ordered list),
rows (ordered list)`, plus lookup indexes:
- `columns_by_id`
- `column_id_by_name_key`
- `rows_by_id`
- `row_id_by_label_key`

It is built from DB rows on load.

**`Sheets.Op.parse(map)`** turns contract §6 `Op` JSON, with string keys,
into typed structs such as `%Op.SetCells{cells: [...]}`. It returns
`{:error, :invalid_op, msg}` on malformed input. It never calls
`String.to_atom`: op types go through an explicit whitelist.

**`Sheets.Values`**:
- `cast(column_type, json_value)` returns `{:ok, stored}` or
  `{:error, :invalid_value}`.
- `convert(from_type, to_type, value)` is used by `change_column_type`:
  - number → text: `to_string`
  - text → number: parse, and fail if it can't
  - text → date: ISO 8601 only
  - text → boolean: `true`/`false`, case-insensitive
  - boolean ↔ number: 1 and 0
  - anything → text: always works

**`Sheets.Engine.apply(state, op, limits)`** returns one of:
- `{:ok, new_state, applied_op, effects}`: `applied_op` is the normalized
  contract `AppliedOp` map, with ids filled in and values cast;
- `{:error, code, message, meta}`: `code` is from contract §8.

`effects` is a list of DB-level instructions that the Persister turns into
Multi steps, for example:
- `{:insert_rows, [...]}`
- `{:update_row_values, row_id, values}`
- `{:shift_positions, :rows, from, delta}`

The engine enforces every rule in contract §6:
- ids exist
- name and label uniqueness, via the `*_key` indexes
- the label column is protected
- values match their types
- positions are in range
- the size caps come from `limits` (config)

It has no side effects, so it gets the bulk of the tests (§11).

`Sheets.Engine.create(attrs, owner)` builds the initial state and effects
for `create_sheet`: the label column, optional columns, and optional rows.
It is used both by `Sheets.create_sheet/2` and by the AI's `create_sheet`
tool.

## 5. Sheet processes

**`Sheets.Server`** is a GenServer, `restart: :transient`, registered via
`{:via, Registry, {SpreadSheetAi.Sheets.Registry, sheet_id}}`. It is started
under the DynamicSupervisor `SpreadSheetAi.Sheets.ServerSupervisor`.

- **`init/1`** loads the sheet, its columns and its rows into `State`. It
  uses `handle_continue` so the load doesn't block the caller. If the sheet
  doesn't exist, it stops with `:not_found`.
- **`apply_op(sheet_id, op, actor, opts)`** is a `call`:
  1. `Engine.apply`
  2. `Persister.run(effects, sheet_id, new_version, applied_op, actor, opts)`,
     which runs in one `Repo.transaction`. The version bump uses
     `UPDATE sheets SET version = version + 1, updated_at = now() WHERE id = ? AND version = ?`,
     so if the in-memory version is out of step with the DB, the transaction
     fails.
  3. On commit, it replaces its state, broadcasts
     `{:op_applied, %{version, applied_op, actor, client_op_id}}` on PubSub
     topic `"sheet_events:<id>"`, and replies `{:ok, version, applied_op}`.
  4. On a DB error, it replies `{:error, :internal_error, …}` and **stops**,
     so the next call reloads a fresh state from Postgres.
- **Reads** are `call`s served from memory, never from the DB:
  - `snapshot/1`
  - `describe/1`: columns, row count and version
  - `read_rows/2`: offset, limit and optional columns, capped by
    `read_max_rows`
  - `read_cells/2`: row labels × column names
  - `find_rows/2`: case-insensitive substring match on labels, capped
- **Idle stop:** every reply returns a timeout of `idle_timeout` (config,
  15 minutes by default). `handle_info(:timeout)` returns
  `{:stop, :normal, state}`.

**`Sheets.Runtime.call(sheet_id, msg)`**:
- It calls `ensure_started(sheet_id)`, which is `DynamicSupervisor.start_child`
  treating `{:already_started, pid}` as success, and then
  `GenServer.call`.
- If the server exits during the call with `:noproc` or `:normal`, because
  it stopped from idle at that moment, it retries once.

**Creating a sheet** skips the server:
1. `Sheets.create_sheet/3` runs `Engine.create` plus the Persister in one
   transaction. This writes version 1 and the first change-log row.
2. It returns the snapshot. The server starts later, on first use.

**Why this is enough for RT-4 and P-5:**
- Versions only go up inside a committed transaction.
- A broadcast only happens after the commit.
- A crashed or restarted server reloads the committed version.
- Clients that missed broadcasts see a version gap and request a snapshot.

## 6. Web layer: socket and sheet channel

**Socket authentication** (contract §4):
- `SocketTokenController.show` signs
  `Phoenix.Token.sign(Endpoint, "user socket", %{user_id, session_id})`.
- `endpoint.ex` adds
  `socket "/socket", SpreadSheetAiWeb.UserSocket, websocket: [auth_token: true], longpoll: false`.
- `UserSocket.connect(_params, socket, %{auth_token: token})` checks the
  token with `max_age: 86_400`. It then loads the session with a new
  `Accounts.fetch_active_session/1`, which reuses
  `SessionQueries.active/1` and joins on active users, and assigns
  `current_user` and `current_session`.
- `id/1` returns `"user_socket:<session_id>"`, so that revoking a session
  can disconnect its socket later.

**`SheetChannel`, `"sheet:<id>"`:**
- **join:** `Sheets.snapshot(id)` → `{:ok, %{sheet: SheetJSON.sheet(s)}, socket}`.
  After joining, it subscribes to `"sheet_events:<id>"`, tracks presence
  (`Presence.track(self(), "sheet:<id>", user_id, %{})`), and pushes
  `participants`.
- **`handle_in("op")`:**
  1. `Op.parse`
  2. `Sheets.apply_op(id, op, Actor.user(user), client_op_id: …)`
  3. Reply `{:ok, %{version}}`, or `{:error, Errors.from_code(code, message, meta)}`.
- **`handle_in("snapshot")`** replies with a new snapshot.
- **`handle_info({:op_applied, ev})`** pushes `op_applied` via `SheetJSON`.
- **Presence:** `intercept ["presence_diff"]`. `handle_out` recomputes the
  user list from `Presence.list/1`, batch-loads the `UserRef`s, and pushes
  `participants`.

**REST** (contract §3): `SheetController.index/show/create` and
`ConversationController.index/show/create`, with routes in the existing
`scope "/api", … pipe_through [:api, :require_auth]`.

### 7.3 `ConversationChannel`, `"conversation:<id>"`

The channel process is a Sagents subscriber. Sagents delivers agent events
with `send/2` to each subscribed process, **not** over PubSub.
`AgentSubscriberSession` (generated) is the pure state helper for this and
is reused as is.

**join:**
1. Load the conversation, its display messages (`MessageJSON`) and its
   linked sheets.
2. `Sagents.Subscriber.subscribe_to_agent(subs, agent_id, tagged: true)`,
   where `agent_id = Coordinator.conversation_agent_id(id)`. If no agent is
   running, the subscription stays pending.
3. `PubSub.subscribe("agent_server:presence")`, so a pending subscription is
   revived when an agent starts (`handle_presence_diff`).
4. `PubSub.subscribe("conversation_events:<id>")` for app events (below).
5. `Coordinator.track_conversation_viewer(id, user)`.
6. Reply with contract §7.1, `status: not_started` if no agent is running.

Sagents tracks viewers on the same topic, `"conversation:<id>"`, so
`intercept ["presence_diff"]` turns presence changes into `participants`
pushes, as in the sheet channel. The AgentServer also subscribes to this
topic and ignores unknown messages. The app therefore sends its own events
on the separate `"conversation_events:<id>"` topic, not on the channel
topic.

**`send_message`:**
1. `Coordinator.ensure_agent_session_running(%{conversation_id, current_scope: Scope.for_user(user), sagents_subs})`.
2. Build the model-visible message: `Message.new_user!("[#{display_name}]: #{text}")`,
   with metadata `%{"sender_user_id" => id}`.
3. Build the display message: `Message.new_user!(text)`, with the same
   metadata.
4. `AgentServer.add_message(agent_id, llm_msg, display: display_msg)`.

Edge cases:
- `add_message` queues the message itself if a run is in progress (CS-4).
- **Known race:** two users sending while the agent is idle can get
  `{:error, "Cannot execute…running"}` even though the message was
  accepted. Treat that error as success, log it, and cover it with a
  fake-model test (§11).

**`cancel`:** `AgentServer.cancel(agent_id)`. If the agent isn't running,
reply `not_running`.

**`open_sheet`:**
1. `Sheets.link(conversation_id, sheet_id, :opened)`.
2. Broadcast `{:sheets_changed}` on `"conversation_events:<id>"`.
3. Reply with the `LinkedSheet`.

**Event translation.** A pure `ConversationEvents.translate/2` turns each
event into zero or more contract pushes, so it can be unit-tested:

| Sagents event (`{:agent, tag, ev}`) | Push |
|---|---|
| `{:llm_deltas, deltas}` | `stream_delta` with the new text, merged through `AgentSubscriberSession.handle_llm_deltas` |
| `{:display_message_saved, dm}` | `stream_reset` (if streaming), then `message` |
| `{:display_message_updated, dm}` | `message_updated` |
| `{:tool_call_identified, info}` / `{:tool_execution_update, st, info}` | `tool_status` |
| `{:status_changed, st, _}` | `status` (`:interrupted` and `:paused` are not used, because HITL is off) |
| `{:message_queued, msg}` | `message_queued`. The sender comes from `msg.metadata`, or is parsed from the `[Name]:` prefix |
| `{:conversation_title_generated, title, _}` | `title` |
| `{:chain_error, err}` | `status` `error` with the formatted message |
| `{:agent_shutdown, _}` | the subscription goes back to pending, and `status` `idle` is pushed |
| `{:llm_message, _}`, `{:llm_token_usage, _}`, `{:state_restored, _}`, `{:todos_updated, _}` | ignored |

Events on `"conversation_events:<id>"` (from tools and `open_sheet`):
- `{:sheets_changed}`: reload the links and push `sheets`.
- `{:focus_sheet, sheet_id, reason}`: push `focus_sheet`.

Only subscribers of this conversation receive these, which is what UI-4
requires.

### 7.4 Model configuration (OpenRouter)

- **Dependencies:** add `{:sagents, "~> 0.15.1"}` and
  `{:req_llm, "~> 1.24"}`. `req_llm` is an optional dependency of LangChain,
  and `ChatReqLLM` only compiles when it is present.
- **Config:**

  ```elixir
  config :spread_sheet_ai, :ai,
    model: "openrouter:<vendor>/<model>",
    title_model: "openrouter:<cheap model>",
    max_tokens: 4096
  ```

  Both models are overridable at runtime via `AI_MODEL` and
  `AI_TITLE_MODEL`.
- **Where the models are built:** `SpreadSheetAi.Agents.ChatModels.main/0`
  and `title/0` build `ChatReqLLM.new!(%{model: …, stream: true, max_tokens: …})`.
  Tests replace them (§11) via `config :spread_sheet_ai, :ai, chat_model_builder: …`.
- **API key:** ReqLLM reads `OPENROUTER_API_KEY` itself. `runtime.exs` raises
  in prod if it's missing, and dev logs a warning.
- **Unverified models:** set `config :req_llm, warn_unverified_models: false`,
  since OpenRouter model ids are often missing from ReqLLM's catalog.
- **Choosing the model:** pick the default during Phase 8, once the tools
  exist, by running the §8 tool scenarios against 2–3 candidate models.
  Record the choice in `config/config.exs`. Until then, Phase 6 uses any
  model for a plain-chat smoke test.

## 8. AI tools and context

### 8.1 `Middleware.SheetTools`

**`tools/1`** returns the tools below. Each tool gets `context.conversation_id`
and `context.agent_id` from Sagents.

**`before_model/2`** injects the linked-sheet summary (AI-1) at the start of
each run:
- It loads the `conversation_sheets` for `state.conversation_id`.
- It renders a delimited `<linked_sheets>` block listing each sheet's id,
  name, columns with their types, and row count. It includes no values.
- **First choice:** rewrite the dedicated system-message block in
  `state.messages`, so the context doesn't pile up.
- **Fallback, if Sagents doesn't allow that:** prepend the block to the
  latest user message, as the Sagents middleware guide documents. In that
  case older blocks stay in the history, and Summarization handles long
  sessions.
- **Deciding which:** a spike at the start of Phase 8 settles it.

### 8.2 Tools

Tools refer to sheets by id, rows by label and columns by name. The
`Sheets` API converts those to ids.

| Tool | Arguments | Result (JSON text) |
|---|---|---|
| `list_sheets` | — | `[{id, name, rows, columns}]` |
| `open_sheet` | `sheet_id` | structure: columns `[{name, type, is_label}]`, `row_count`, `version` |
| `create_sheet` | `name`, `label_column_name?`, `columns?: [{name, type}]`, `rows?: [{label, values: {column: value}}]` | the new sheet's id and structure |
| `read_rows` | `sheet_id`, `offset?`, `limit?`, `columns?: [name]` | `{rows: [{label, values}], total, offset}` |
| `read_cells` | `sheet_id`, `rows: [label]`, `columns: [name]` | `{cells: {label: {column: value}}}` |
| `find_rows` | `sheet_id`, `query` | `{rows: [label], truncated}` |
| `rename_sheet` | `sheet_id`, `name` | `{version}` |
| `add_column` | `sheet_id`, `name`, `type`, `position?` | `{version}` |
| `rename_column` | `sheet_id`, `column`, `new_name` | `{version}` |
| `change_column_type` | `sheet_id`, `column`, `type` | `{version}` |
| `move_column` | `sheet_id`, `column`, `position` | `{version}` |
| `delete_column` | `sheet_id`, `column` | `{version}` |
| `add_rows` | `sheet_id`, `rows: [{label, values: {column: value}}]`, `position?` | `{version, added}` |
| `delete_rows` | `sheet_id`, `labels: [label]` | `{version, deleted}` |
| `move_row` | `sheet_id`, `label`, `position` | `{version}` |
| `set_cells` | `sheet_id`, `cells: [{row, column, value}]` | `{version, updated}` |

Every tool call that touches a sheet also:
1. applies the op with `Actor.agent(conversation_id, title)`;
2. calls `Sheets.link(conversation_id, sheet_id, kind)`, where `kind` is
   `created`, `opened`, `read` or `written`;
3. broadcasts `{:focus_sheet, id, kind}` and `{:sheets_changed}` on
   `"conversation_events:<id>"`. The focus event goes out before the tool
   returns, which gives the contract §7.3 ordering.

**Errors (AI-4).** Tool functions return `{:error, text}`. ChatReqLLM
forwards only the text to the model, not an error flag, so the text must
say it is an error and how to fix it:

```
ERROR unknown_column: column "Q3" does not exist in sheet "P&L 2026".
Existing columns: Line item, Q1, Q2.
```

Argument definitions are strict: required fields, enum `type`, and
`additionalProperties: false`. Tool modules rescue nothing on purpose,
because LangChain already turns exceptions into error results.

### 8.3 System prompt

A short fixed prompt that covers:
- **Role:** the AI is a spreadsheet copilot.
- **Speakers:** user messages begin with `[Name]:`, and several people may
  be talking in the same session.
- **Sheets:** only use sheets from `<linked_sheets>`, or ones found through
  `list_sheets` and `open_sheet`.
- **Reading:** read values with the read tools and never guess them. Keep
  reads small.
- **Writing:** prefer one `set_cells` or `add_rows` call over many small
  ones.
- **Errors:** after an `ERROR`, fix the arguments and retry.
- **Formulas:** they aren't supported; write literal values.

## 11. Testing strategy

- **Engine and Values:** pure unit tests, table-driven over ops and rules.
  These form most of the suite.
- **Server and Runtime:**
  - `start_supervised!` and `DataCase`.
  - Crash recovery: kill the server with `Process.exit(pid, :kill)` and
    assert that a reload gives the same version.
  - Idle stop: set a 10 ms idle timeout and use `Process.monitor` plus
    `assert_receive {:DOWN, …}`.
  - Concurrency: 50 concurrent `apply_op` calls through
    `Task.async_stream`, then assert that versions go 1..50 and the change
    log has no gaps.
- **Channels:** `Phoenix.ChannelTest` with a `SocketCase` helper that
  signs a token for a fixture user. Assert on `assert_push` and
  `assert_broadcast`.
- **Agent tests with no real model** (NF-4):
  - `SpreadSheetAi.Test.ScriptedChatModel` implements the
    `LangChain.ChatModels.ChatModel` behaviour. It returns queued, scripted
    responses (text, or tool calls) and reports deltas to the callbacks.
  - It's injected through the `chat_model_builder` config.
  - Sagents ships no fake model, which is why we write our own.
  - If the behaviour turns out to be impractical to implement, fall back to
    stubbing `ReqLLM.stream_text` with Mimic, as the Sagents guides do.
- **Tools:** each tool function is called directly with a context map,
  with no agent involved.
- **Manual only:** real OpenRouter calls happen only in the manual runs of
  Phases 6, 8 and 9, never in `mix test`.

## 12. Risks and open points

| Risk | Mitigation |
|---|---|
| Sagents 0.x API churn | Pin `~> 0.15.1`. Keep all generated code in `agents/` and `conversations/`, and our own glue in separate modules |
| Cheaper models are unreliable at calling tools | Strict argument definitions, error text the model can act on, bulk tools, model chosen by config, tested in Phase 8 |
| Linked-sheet context piles up in history | Phase 8 spike (§8.1). Summarization middleware |
| Two users sending at once while idle (the Sagents race) | Treat the error as success, plus a regression test (§7.3) |
| A turn in progress is lost if the node crashes (Sagents persists state only at lifecycle points) | Accepted for the POC. Messages already written stay visible |
| The agent stops after 10 minutes idle even while people are viewing | Harmless: the next `send_message` restarts it from persisted state. Optionally call `AgentServer.touch/1` while viewers are present |
| The generated code differs from app conventions (Repo calls in generated modules) | Accepted inside the generated `conversations/` and `agents/` namespaces. Our own code follows the conventions |
